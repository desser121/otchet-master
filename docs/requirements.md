# Требования (MVP)

Статус: утверждено в продуктовом интервью. Версия документа: v1.

## 1. Функциональные требования

### 1.1 Реквизиты мастера
- FR-1: при первом запуске мастер заполняет реквизиты один раз: имя, телефон, город.
- FR-2: реквизиты подставляются в шапку каждого отчёта.
- FR-3: реквизиты можно изменить в настройках.

### 1.2 Создание работы
- FR-4: мастер создаёт новую работу: дата, адрес объекта, имя клиента, телефон клиента.
- FR-5: дата по умолчанию — текущая, редактируется.
- FR-6: добавление фотографий обязательно (минимум одна).
- FR-7: описание работ — голосом (распознавание на устройстве) или текстом.
- FR-8: материалы — список строк (название, количество), без цен.

### 1.3 Генерация отчёта
- FR-9: «Создать отчёт» — AI структурирует текстовое описание в отчёт (JSON).
- FR-10: при отсутствии сети генерация помечается «ожидает сети»; отчёт можно создать вручную.
- FR-11: ручной режим доступен всегда как запасной вариант.
- FR-12: если AI вернул ошибку или мусор — кнопка «Повторить» и предложение ручного режима.
- FR-13: результат AI обязательно редактируется пользователем перед созданием PDF.

### 1.4 PDF
- FR-14: PDF создаётся на устройстве из структурированных данных (JSON).
- FR-15: PDF можно отправить клиенту через системное меню «Поделиться».
- FR-16: PDF создаётся и без сети (ручной режим).

### 1.5 История
- FR-17: список прошлых работ с возможностью открыть отчёт и переотправить PDF.
- FR-18: данные работы, фото и отчёт сохраняются локально и синхронизируются в облако при появлении сети.

### 1.6 Синхронизация
- FR-19: локальная база Room — источник истины.
- FR-20: фоновая синхронизация при появлении сети: работа → фото → отчёт → реквизиты.
- FR-21: статусы элементов: «сохранено на устройстве» / «загружается» / «готово».

## 2. Нефункциональные требования

### 2.1 Офлайн
- NFR-1: создание работы, фото, текст, ручной отчёт, PDF — работают без сети.
- NFR-2: потеря сети не приводит к потере данных.

### 2.2 Производительность
- NFR-3: AI-генерация отчёта — синхронная, целевое время ответа не более 10–15 секунд.
- NFR-4: приложение работает на устройствах среднего класса (API 33+).

### 2.3 Безопасность и приватность
- NFR-5: фото и личные данные не отправляются в AI.
- NFR-6: секреты только на серверной стороне (edge-функции), в клиенте — только анонимный ключ.
- NFR-7: доступ к данным пользователя — через Row Level Security (RLS) Supabase.
- NFR-8: ничего лишнего не логируется; личные данные клиентов не попадают в репозиторий.

### 2.4 Поддержка и сопровождение
- NFR-9: проект сопровождается одним разработчиком (владельцем), без глубокого опыта.
- NFR-10: минимальная стоимость инфраструктуры (0–10 $/мес).

## 3. Критический пользовательский путь (для тестирования)

Новая работа → фото → описание голосом/текстом → материалы → «Создать отчёт» (AI) → редактирование → PDF → отправка клиенту → работа видна в истории.

Офлайн-вариант: тот же путь без сети, генерация через ручной режим.

## 4. Тестовые требования

- Unit-тесты: логика JSON→отчёт, статусы синхронизации.
- API/edge-функция: генерация отчёта, обработка ошибок AI.
- Integration-тесты: критический пользовательский путь (локальная БД + синхронизация).
- Безопасность: RLS, отсутствие доступа к чужим данным (IDOR-проверки).
