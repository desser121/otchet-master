# API

Статус: утверждено в продуктовом интервью (блок 12).

## Общие принципы

- Используются стандартные REST-эндпоинты Supabase (PostgREST) + Storage + одна edge-функция.
- Вся офлайн-логика живёт на телефоне; API — тонкий слой: выгрузка и чтение данных, генерация отчёта.
- Авторизация: JWT анонимной сессии в заголовке `Authorization: Bearer <token>`.
- Доступ к данным ограничен RLS по `auth.uid()`.
- Версионирование: для MVP не требуется (единственный клиент), заголовок `Accept: application/vnd.pgrst.version` при необходимости.

## Формат ошибок

Все ошибки возвращаются в формате:

```json
{ "error": { "code": "string", "message": "string" } }
```

Основные коды:

| Код | Значение |
|---|---|
| `UNAUTHORIZED` | нет/неверный токен |
| `FORBIDDEN` | RLS не пропустила |
| `VALIDATION` | невалидные данные |
| `AI_ERROR` | ошибка AI-провайдера |
| `AI_TIMEOUT` | таймаут AI-провайдера |
| `AI_INVALID_RESPONSE` | AI вернул невалидный JSON |
| `NOT_FOUND` | ресурс не найден |

## Синхронизация (телефон → облако)

### Реквизиты мастера
- `POST /rest/v1/master_profiles` — создать/обновить (`upsert`)
- `GET /rest/v1/master_profiles?user_id=eq.<uid>` — прочитать

### Работы
- `POST /rest/v1/jobs` — выгрузить работу
- `GET /rest/v1/jobs?user_id=eq.<uid>&order=created_at.desc` — история (восстановление)

### Фото
- `POST /storage/v1/object/photo/{job_id}/{photo_id}.jpg` — загрузка файла
- После загрузки: `PATCH /rest/v1/photos` с `cloud_url`

### Отчёт
- `POST /rest/v1/reports` — сохранить готовый отчёт (после редактирования)
- `GET /rest/v1/reports?job_id=eq.<id>` — прочитать

### Материалы
- `POST /rest/v1/materials` — выгрузить список
- `GET /rest/v1/materials?job_id=eq.<id>` — прочитать

## AI-генерация (edge-функция)

`POST /functions/v1/generate-report`

Запрос:

```json
{
  "description": "Поклеил обои в спальне, выровнял стены, заменил плинтусы...",
  "materials_hint": ["обои 5 рулонов", "клей для обоев"],
  "master_name": "Иван Петров",
  "client_name": "Сергей",
  "date": "2026-08-12"
}
```

Ответ (200):

```json
{
  "work_performed": "Поклейка обоев в спальне...",
  "materials": ["обои — 5 рулонов", "клей для обоев"],
  "notes": ""
}
```

Ошибки:

- 401 `UNAUTHORIZED` — нет сессии
- 400 `VALIDATION` — пустое описание
- 502 `AI_ERROR` / 504 `AI_TIMEOUT` / 422 `AI_INVALID_RESPONSE` — проблемы провайдера

Клиент при ошибке AI: показывает «Повторить» и предлагает ручной режим.

## Ограничения и rate limits

- Опираемся на лимиты Supabase по тарифу.
- Edge-функция `generate-report` — только аутентифицированные вызовы (анонимная сессия), защита от злоупотреблений через проверку JWT.
- Фото: проверка размера и типа на клиенте перед загрузкой.

## Безопасность

- Никаких секретов в клиенте — только `anon key`.
- AI API key живёт в секретах edge-функции, на устройство не попадает.
- RLS защищает все таблицы; IDOR исключён тем, что доступ строится только через `auth.uid()`.
