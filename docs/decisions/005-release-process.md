# ADR-005: Релиз-процесс — тег + GitHub Actions, APK для тестовой группы

Статус: **Принято** (продуктовое интервью, блок «Релизы»)

## Контекст

Нужен простой процесс выпуска обновлений для MVP. Один разработчик, первая аудитория — тестовая группа мастеров. Play Store отложен.

## Рассматриваемые варианты

1. **Тег `vX.Y.Z` → GitHub Actions собирает и подписывает APK → GitHub Release**
   - Плюсы: автоматизация, changelog из тега, повторяемость, ссылка для тестовой группы.
   - Минусы: нужна настройка secrets (keystore).
2. **Релиз вручную** (сборка локально + загрузка файла на GitHub)
   - Плюсы: ничего не настраивать.
   - Минусы: ручная рутина, риск потери подписи/версий.

## Решение

Вариант 1. Распространение — APK тестовой группе через GitHub Release. Play Store — позже, отдельным шагом (AAB + service account).

## Последствия

- Keystore и пароли живут только в repo secrets (шифрованные), в Git не попадают.
- Обновление приложения для тестовой группы — повторная установка APK из нового Release.
- При переходе на Play Store добавляется сборка AAB, существующий процесс не ломается.
