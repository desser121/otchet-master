# ADR-002: Бэкенд — Supabase (BaaS), без собственного сервера

Статус: **Принято** (продуктовое интервью, блок 7)

## Контекст

Нужен минимальный бэкенд: база, хранилище фото, анонимная аутентификация и одна AI-функция. Один разработчик, минимальная стоимость, быстрая разработка.

## Рассматриваемые варианты

1. **Supabase (Postgres + Storage + Auth + edge-функции)**
   - Плюсы: не нужно писать свой сервер; бесплатный тариф; RLS; офлайн-синхронизация; быстро.
   - Минусы: привязка к BaaS; лимиты тарифа.
2. **Собственный сервер (FastAPI + PostgreSQL + R2)**
   - Плюсы: полный контроль.
   - Минусы: два компонента для поддержки, нужен деплой и VPS; сложнее для новичка.

## Решение

Supabase. Данные: Postgres. Фото: Storage (bucket `photo`). Сессия: анонимная (ADR-003). AI: edge-функция `generate-report`.

## Последствия

- Нет собственного сервера и VPS.
- Логика офлайна живёт на устройстве.
- Затраты: 0–5 $/мес на старте.
- Замена BaaS в будущем возможна, но потребует переноса схемы и RLS.
