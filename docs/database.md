# Модель данных

Статус: утверждено в продуктовом интервью (блок 10). Документ описывает локальную (Room) и облачную (Postgres) модели. Они совпадают по смыслу; Room хранит также локальные пути к файлам и статусы синхронизации.

## ER-диаграмма

```
User (анонимный, Supabase Auth)
 │
 ├── MasterProfile (1:1)
 │
 └── Job (1:N)
       ├── Photo (1:N)
       ├── Material (1:N)
       └── Report (1:1)
```

## Сущности

### User
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | uuid | да | создаётся Supabase при анонимной сессии |

Зачем: привязка всех данных к конкретному устройству/сессии. Никаких персональных полей.

### MasterProfile
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| user_id | uuid (PK/FK) | да | 1:1 с User |
| name | text | да | имя мастера, в шапку отчёта |
| phone | text | да | телефон мастера |
| city | text | да | город |

Зачем: реквизиты заполняются один раз и подставляются в каждый отчёт.
Индексы: PK по user_id.
Не храним: документы, ИНН, паспорт, фото.

### Job
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | uuid | да | |
| user_id | uuid (FK) | да | владелец |
| date | date | да | дата работы |
| address | text | да | адрес объекта |
| client_name | text | да | имя клиента |
| client_phone | text | да | телефон клиента |
| created_at | timestamptz | да | |
| updated_at | timestamptz | да | |
| sync_status | text | нет | только в Room: LOCAL/UPLOADING/SYNCED |

Зачем: одна выездная работа = один отчёт. Клиент пока просто поля в работе (без отдельной сущности).
Индексы: PK(id), (user_id, created_at DESC).
Не храним: паспортные данные клиента, лишние контакты.

### Photo
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | uuid | да | |
| job_id | uuid (FK) | да | принадлежит работе |
| local_path | text | да | путь на устройстве (Room) |
| cloud_url | text | нет | URL в Storage после загрузки |
| position | int | да | порядок в отчёте |
| created_at | timestamptz | да | |
| sync_status | text | нет | только в Room |

Зачем: обязательные фото работы. Без подписей в MVP.
Индексы: PK(id), (job_id).
Не храним: exif-данные с геолокацией (удалять при сохранении), лица без согласия — нет, это обычные фото работ.

### Material
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | uuid | да | |
| job_id | uuid (FK) | да | |
| name | text | да | название материала |
| quantity | text | нет | количество (строка, напр. «2 рулона») |

Зачем: простые строки без цен — счёт вне MVP.
Индексы: PK(id), (job_id).

### Report
| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| id | uuid | да | |
| job_id | uuid (FK) | да | 1:1 с Job |
| work_performed | text | да | структурированное описание работ |
| materials | jsonb | нет | массив строк, продублирован из Material для удобства AI |
| notes | text | нет | примечания |
| source | text | нет | `ai` / `manual` |
| pdf_local_path | text | нет | путь к PDF на устройстве |
| created_at | timestamptz | да | |
| updated_at | timestamptz | да | |
| sync_status | text | нет | только в Room |

Зачем: результат AI (или ручного режима) в структурированном виде. PDF собирается на устройстве из этих данных.
Индексы: PK(id), (job_id).
Не храним: произвольный HTML/PDF от AI.

## Облако vs устройство

- Postgres хранит: User, MasterProfile, Job, Photo (cloud_url), Material, Report.
- Room дополнительно хранит: local_path, sync_status, pdf_local_path.
- RLS: каждая таблица — `user_id = auth.uid()` (анонимная сессия). Чужие данные недоступны.

## Открытые вопросы (для будущих версий)

- Перенос данных между устройствами (потребует пин-кода/входа) — решено не делать в MVP.
- Счёт → сущность Invoice + цены в Material.
- База клиентов → сущность Customer и связь Job→Customer.
