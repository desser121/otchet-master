# Безопасность

## Принципы

- Проект публичный (GitHub) — в репозитории никогда не появляются секреты и персональные данные.
- Всё личное и конфиденциальное хранится только на устройстве и в облаке, не в Git.

## Что нельзя коммитить

- API-ключи, пароли, токены, приватные ключи
- Production credentials
- Реальные персональные данные пользователей
- Реальные фотографии клиентов
- Реальные документы/отчёты
- Файлы `.env` (в .gitignore), локальные БД, дампы

## Управление секретами

- `.env.example` — пример, коммитится.
- `.env` — реальные значения, в .gitignore.
- Edge-функции: секреты через `supabase secrets set` (или env у облачного провайдера), на устройство не попадают.
- В Android-клиенте — только `SUPABASE_URL` и `SUPABASE_ANON_KEY` (публичные по своей природе).

## Аутентификация и авторизация

- Анонимная сессия Supabase (решение блока 8). JWT-токен хранится в защищённом хранилище устройства (EncryptedSharedPreferences/Keystore).
- Вся доступ к данным — через RLS: каждая таблица имеет политику `user_id = auth.uid()`.
- Edge-функция `generate-report` проверяет JWT перед выполнением.

## Защита от типовых угроз

| Угроза | Мера |
|---|---|
| IDOR (доступ к чужим данным) | RLS по `auth.uid()`; доступ к файлам Storage по bucket-политике на владельца |
| Подмена данных при синхронизации | сервер принимает только строки с `user_id = auth.uid()` |
| Злоупотребление AI-функцией | JWT-проверка, ограничение длины `description`, лимиты на уровне edge-функции |
| Секреты в клиенте | AI API key только в секретах серверной функции |
| Большие/вредоносные файлы | проверка размера и MIME-типа на клиенте и в Storage bucket |
| Утечка фото | bucket приватный, доступ через signed URL/RLS |
| Сниффинг | HTTPS обязательно |

## Приватность данных

- В AI отправляется только текст описания и базовые реквизиты (имя, город, дата, имя клиента). Фото, адреса, телефоны — нет.
- Логи: не логировать тексты отчётов и персональные данные. Логировать только коды ошибок.
- EXIF-данные фото (геолокация) — удалять при загрузке.
